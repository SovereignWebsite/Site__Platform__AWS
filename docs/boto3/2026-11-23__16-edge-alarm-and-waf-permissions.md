# 16: WAF on the distribution, the CloudFront cost alarm, and cloudwatch:AlarmActions

For iam.aws.a, cloudformation.aws.a and security.aws.a (vault-access 0.2.8 and 0.2.9, vault-edge.yaml 0.5.0). AWS's public pages only, read 23 Nov 2026.

| # | Question | Verdict | Source and note |
|---|---|---|---|
| 1 | Setting WebACLId (WAFv2 ARN) on a distribution: any wafv2 permission beyond cloudfront:CreateDistribution / UpdateDistribution? | None documented | AssociateWebACL API: "Use this for all resource types except for Amazon CloudFront distributions. For Amazon CloudFront, call UpdateDistribution for the distribution and provide the Amazon Resource Name (ARN) of the web ACL". The WAF guide's "Permissions for AssociateWebACL" says the same and, unlike every other resource type it lists, names no wafv2 permission for CloudFront. The distribution handler lists none either. Whether CloudFront checks the caller for wafv2:GetWebACL behind the scenes is not stated: to confirm. GetWebACL on that one ACL is read-only, so keeping it as a guess costs nothing; drop it if the first deploy works without it. |
| 2 | Cost alarm: AWS/CloudFront, Requests, DistributionId and Region=Global, us-east-1 only, free, no additional metrics | Confirmed | "The value for Namespace is always AWS/CloudFront"; dimensions DistributionId and "Region ... is always Global"; "To get the CloudFront metrics from the CloudWatch API, you must use the US East (N. Virginia) Region (us-east-1)" (CloudFront DG, CloudWatch metrics). "The following default metrics are included for all CloudFront distributions, at no additional cost: Requests ..." (viewing metrics); "additional metrics" are a separate, paid opt-in. So the alarm must be in us-east-1, the edge stack. The CloudWatch alarm itself is billed as an alarm (CloudWatch pricing, not re-read). |
| 3 | cloudwatch:AlarmActions on PutMetricAlarm: name, multivalued, ForAllValues with no actions | Confirmed, with a gap | SAR for CloudWatch: PutMetricAlarm lists `cloudwatch:AlarmActions`, "Filters access by defined alarm actions", type ArrayOfString (multivalued). IAM: ForAllValues "returns true if every context key value in the request matches ... It also returns true if there are no context keys in the request", so an alarm with no actions passes. **Gap:** the key is described as "alarm actions"; whether it also covers OKActions and InsufficientDataActions is not stated. If not, an alarm could send its OK or insufficient-data notices anywhere. To confirm, or deny PutMetricAlarm requests that carry those (no documented key for them was found). |
