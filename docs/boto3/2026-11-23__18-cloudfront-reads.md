## Addendum, 20:25 UTC: field names in logging v2 records (for architect.aws.a)

- **Field names are the W3C ones.** The standard logs field reference and the logging v2 page list the fields as `date`, `time`, `x-edge-location`, `sc-bytes`, `c-ip`, `cs-method`, `cs(Host)`, `cs-uri-stem`, `sc-status`, `cs(Referer)`, `cs(User-Agent)`, `cs-uri-query`, `x-edge-request-id`, `x-host-header`, `time-taken` and so on; v2 adds a selectable subset of real-time fields. Output formats for v2: "JSON, Plain, w3c, Raw, Parquet (Amazon S3 only)", fixed when the delivery destination is created. The pages read show no JSON sample, so that the JSON keys are spelled exactly as the W3C names is **to confirm**.
- **No `distribution_id` field is documented.** The nearest are `x-host-header` (the Host the viewer sent: the `d111111abcdef8.cloudfront.net` name when the default domain is used, otherwise the alternate domain) and `primary-distribution-id`, which is only for continuous deployment. `{DistributionId}` exists only as an S3 partition path variable, not for Firehose and not in the record. Since a delivery source is one distribution, the twin should know the distribution from the delivery (or its Firehose stream), not from a record field; drop `distribution_id` from the record map, or mark it as the twin's own addition.
