| # | Claim | Verdict | Source and note |
|---|---|---|---|
| 1 | Endpoint cloudfront.amazonaws.com, path /2020-05-31/, SigV4 us-east-1 | Confirmed | botocore: protocol `rest-xml`, `signatureVersion` v4, `globalEndpoint` cloudfront.amazonaws.com, signing name `cloudfront`; ListDistributions is `GET /2020-05-31/distribution`, ListFunctions `GET /2020-05-31/function`. endpoints.json: `aws-global`, hostname cloudfront.amazonaws.com, `credentialScope.region` us-east-1, not regionalised. |
| 2 | Paging Marker / NextMarker / MaxItems on ListDistributions and ListFunctions | Confirmed, with one difference | Both requests take `Marker` and `MaxItems` (ListFunctions also `Stage`). DistributionList returns `Marker`, `NextMarker`, `MaxItems`, `IsTruncated`, `Quantity`, `Items`; FunctionList returns `NextMarker`, `MaxItems`, `Quantity`, `Items`, with **no `IsTruncated`**: for functions, page on the presence of `NextMarker`. |
| 3 | ARN in DistributionSummary | Confirmed | `ARN` is a required member of DistributionSummary (with Id, Status, DomainName, Aliases, Origins, WebACLId, Staging and others). |
| 4 | Does CloudFront's API answer a browser CORS preflight? | Partly | SERVICES.md marks Amazon CloudFront "Allows CORS" for API versions 2016-11-25 to 2018-11-05; the current 2020-05-31 is not in that table (the v2 SDK's list stops earlier). Likely, not shown for the current version: one browser call settles it (as for EC2, note 10). |
| 5 | List actions take only Resource "*" | Confirmed | In the CloudFront SAR, `ListDistributions` and `ListFunctions` have no resource type (List access level), so only `"Resource": "*"` matches. |
| 6 | Standard logging v2 is configured through CloudWatch Logs delivery APIs | Confirmed | CloudFront DG, standard logging (v2): "use the CloudWatch PutDeliverySource API operation to create a delivery source for the distribution ... Pass the resourceArn of the distribution. For logType, specify ACCESS_LOGS", then a delivery destination and `CreateDelivery`. Reading the set-up therefore uses the CloudWatch Logs Describe/Get delivery APIs (DescribeDeliveries, DescribeDeliverySources, DescribeDeliveryDestinations), not a CloudFront API. The distribution ARN form is `arn:aws:cloudfront::<acct>:distribution/<id>` (no region). |
| 7 | Object naming of logging v2 delivered through Firehose | Confirmed (Firehose's own rule) | Firehose names S3 objects `<evaluated prefix><stream name>-<stream version>-<year>-<month>-<day>-<hour>-<minute>-<second>-<uuid><file extension>`, with a default prefix `YYYY/MM/dd/HH` (Firehose DG, S3 object name format). So **the distribution id does not appear in the object name** unless the stream's prefix puts it there; it is in the records (the delivered fields). The twin's log names should follow the Firehose pattern, not the legacy `<prefix>/<distribution-id>.<date>...` name of standard logging v1. CloudWatch Logs delivers to Firehose through the service-linked role AWSServiceRoleForLogDelivery (firehose:PutRecord, PutRecordBatch). |
