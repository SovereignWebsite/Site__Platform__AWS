# 20: Route 53 reads, the next area in Dinis's order

The read calls the page would need for Route 53, checked against public material read 23 Nov 2026: botocore route53 2013-04-01 and endpoints.json, the Route 53 SAR, and the AWS SDK for JavaScript v2's SERVICES.md. No AWS call. It also answers the CORS question left open in docs/cloudformation/2026-11-23__reads-and-cors.md (the twin answers 501 for Route 53 until it is settled).

| Item | Finding | Source |
|---|---|---|
| Protocol and endpoint | `rest-xml`, SigV4; one global endpoint, `route53.amazonaws.com`, signed for `us-east-1` (credential scope), not regionalised (a FIPS variant also exists) | botocore metadata; endpoints.json `aws-global` |
| ListHostedZones | `GET /2013-04-01/hostedzone`; request `Marker`, `MaxItems`, `DelegationSetId`, `HostedZoneType`; response `HostedZones`, `Marker`, `IsTruncated`, `NextMarker`, `MaxItems` | botocore |
| GetHostedZone | `GET /2013-04-01/hostedzone/{Id}`; response `HostedZone`, `DelegationSet` (the four name servers), `VPCs` | botocore |
| ListResourceRecordSets | `GET /2013-04-01/hostedzone/{Id}/rrset`; paging is not a marker but a triple: request `StartRecordName`, `StartRecordType`, `StartRecordIdentifier`; response `IsTruncated`, `NextRecordName`, `NextRecordType`, `NextRecordIdentifier` | botocore |
| IAM | `ListHostedZones` has no resource type, so `Resource "*"`; `GetHostedZone` and `ListResourceRecordSets` take the `hostedzone` resource, so they can be scoped to zone ARNs | Route 53 SAR |
| Browser (CORS) | The SDK v2 table marks Amazon Route 53 (AWS.Route53, 2013-04-01) as "Allows CORS"; Route 53 Domains too, Route 53 Resolver not | SERVICES.md |

So the CORS question has the same answer as for EC2 and CloudFront (notes 10 and 18): the SDK's table says yes, and since that table is the SDK's, not a service guide, one browser call confirms it. That is enough to let the twin stop answering 501 and model these three reads; architect.aws.a and cloudformation.aws.a decide.

For the twin: one global host for every region; record paging by name, type and identifier, not a marker; zone ids in paths come as `/hostedzone/Z...` in responses but as bare `Z...` in request paths (botocore's `Id` member), the same split note 08 found for `HostedZoneId` in CloudFormation.
