# Design 01: Lambda and Firehose, the page a first-time user sees

lambda.aws.a@SovereignWebsite.dinis, 23 Nov 2026 ~06:30 UTC. Builds on ux.aws.c's design 01 (docs/design/2026-11-23__01-five-consoles-and-s3-next.md) and on the twin answers on work/lambda.aws.a (5f6f3eb: ListFunctions, GetFunctionConfiguration, ListDeliveryStreams, DescribeDeliveryStream). A design only: no code under site/ from me; site/ changes are requests to aws.c and the console owners.

## 1. The one question

"What runs here, is it working, and where does its output go?" A person who has never opened the AWS console answers it in under a minute, on the twin, without signing in.

## 2. The overview (shared by all five consoles)

One screen, two short lists, and the lines between them:

- **Functions**: one row each. Name; one line of what it does (the function's Description, shown as text); runtime; memory and timeout in words ("256 MB, stops after 30 s"); last changed as a date and "3 days ago"; health as a word and a shape, never colour alone ("OK", "Errors", "Not used").
- **Delivery streams**: one row each. Name; "writes to" with the bucket and prefix as a link into the S3 browser at that prefix; "transforms with" naming the function, as a link to that function's row; buffer in words ("every 15 min or 5 MB"); compression; status.
- **The connection strip** under both lists: `CloudFront logs -> demo-cloudfront-logs -> demo-log-enricher -> s3://...--demo-cloudfront-logs--.../cloudfront/`, each part a link. On the twin it reads the same as on AWS, built from DescribeDeliveryStream (source type, processor ARN, BucketARN and Prefix), never typed by hand.

Empty and error states, in words a newcomer understands:

- No functions: "This account has no Lambda functions in eu-west-2." with the region switch next to it.
- Twin mode, service not answered yet (the transport's 501): "The twin does not show this yet. Nothing was sent to AWS." Never a raw error.
- Real AWS, access refused: "The read role cannot list functions. The permission it needs is lambda:ListFunctions." with a link to the plan that would add it (Desk), so the fix is one step away.

## 3. A function, opened

- **Header**: name, what it does, runtime, memory, timeout, last changed, ARN with a copy button.
- **Code**: the zip it was built from, opened in place with site/zip.js (file list, then any file as highlighted text), no download. On the twin, demo-handler's CodeSize and CodeSha256 match its zip in the deps bucket, so the page can say "Built from lambdas-dependencies/demo-handler==v1.0.0.zip (same SHA-256)" as a checked fact, and "Code not found in a known bucket" when they do not match.
- **Traffic**: invocations, errors and duration for the same hours the log views show, as three small charts with the numbers also in a table (dataviz rule: every chart has a table). Data from CloudWatch GetMetricData once the twin answers it (my next piece); until then the panel says so in the empty-state words above.
- **Connections**: what invokes it (here: the Firehose stream, as transformer) and what it writes or reads. Each is a link to that thing's own page.
- **Settings as code**: the configuration as JSON, read only, with a "Plan a change" button that goes to Desk. This page never changes AWS.

## 4. A delivery stream, opened

- Header: name, status, source type, created date.
- Destination: bucket and prefix (link into Files at that prefix), error prefix, buffer, compression, encryption, transform function (link).
- Newest delivered file: the latest key under the prefix with its time and size, one click to open it as a table (Files' "Latest", ux design 01, section 3 item 4).
- Volume: records delivered per hour, from GetMetricData later; on the twin today, the count of lines per hourly file is already a true measure of what the stream wrote, and the page may show that with the label "lines in delivered files".

## 5. In each console

| Console | Lambda and Firehose look like |
|---|---|
| Map | Nodes for each function and stream, edges for invokes, transforms and writes-to, drawn from the same relations as the connection strip; the logs bucket shows its writer. |
| Timeline | A lane per function (invocations, errors) and per stream (files delivered); the attack pack shows the 22 Nov 09:00 to 11:00 rise in the same place as in the logs. |
| Files | The deps bucket's zips open as code; a stream's prefix opens with "written by demo-cloudfront-logs" above the list. |
| Desk | Findings: a function with no invocations in 30 days; a function whose role can do more than its connections need (with iam.aws.c); a stream with no error prefix. Each ends in a plan or "accept". |
| Command | `lambda ls`, `lambda show <name>`, `firehose ls`, `firehose show <name>`, `who writes <bucket>`, each answering with a card that links into the other four. |

## 6. Layout

At 1024 px and above: functions and streams side by side, the connection strip full width beneath. 720 to 1023 px: stacked, functions first. Below 720 px: one column; each row shows name, health and one line, and opens its own screen with Back. Keyboard: arrows or j/k to move, Enter to open, `/` to filter, as ux design 01 section 3 item 6.

## 7. API calls each view needs

Overview: ListFunctions, then GetFunctionConfiguration per function for its health (ListFunctions returns a subset of each configuration, without State or LastUpdateStatus; found by boto3.aws.a against AWS's ListFunctions reference), ListDeliveryStreams, DescribeDeliveryStream per stream. Rows show at once from ListFunctions; health fills in as each GetFunctionConfiguration answers, with "Checking" until then. Function: GetFunctionConfiguration, a ranged S3 read of the zip, GetMetricData. Stream: DescribeDeliveryStream, ListObjectsV2 on the destination prefix, GetMetricData. No GetFunction (its answer carries a pre-signed link to the code; first note, read permissions), no Invoke, no writes.

## 8. Checks on the twin (for whoever builds it)

1. Overview shows 3 functions and 1 stream; the strip links resolve to rows that exist.
2. demo-handler says "same SHA-256" against its zip; changing one byte of the zip in the twin makes it say "not found".
3. Clicking "writes to" opens the S3 browser at `cloudfront/` in the logs bucket and lists files.
4. With the transport forced to 501 for lambda, the overview shows the twin sentence, and no request leaves the page.
5. At 375 px wide, nothing scrolls sideways and every row opens.

## 9. Security check of this note

- Descriptions, names, keys and log values are untrusted text: always set as text, never as HTML; links only built from fixed patterns for known types (R-002), never from a raw value.
- The page only reads. Every change is a plan for Dinis to approve (Desk).
- Real-AWS mode would need the lambda, firehose and monitoring hosts reachable from the page (connect-src); whether those endpoints answer a browser's CORS preflight is still an open question (first note), to settle from AWS documentation, not by calling AWS.
- No new script or page under site/ from me (R-010).
