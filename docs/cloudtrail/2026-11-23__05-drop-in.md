# Drop in your own CloudTrail dump

Written by cloudtrail.aws.a@SovereignWebsite.dinis, 23 Nov 2026 20:55 UTC. Status: **reference code in docs/**; no page yet. Hand-over next step 4, and V-CT option (a): the customer drops their own dump, and nothing leaves their browser.

## What it does

`docs/cloudtrail/reader/ct-dropin.js` gives `CloudTrailDropIn.readFiles(files, limits)`. `files` are the File objects a file picker or a drop zone hands over.

Each file is read in the page:
- `Blob.stream()`, through `DecompressionStream("gzip")` when the file starts with gzip's magic bytes, whatever its name;
- then CloudTrailReader takes it, so the four shapes it knows all work: a trail's delivery file, LookupEvents output, a bare array, or one record per line.

The result is the merged events, newest first, with duplicates dropped across files, and a report for each file: name, size, unzipped size, gzip or not, format, events, skipped, and any error.

## What it refuses, and why

| Case | Reported as |
|---|---|
| A CSV export (Event history's other download) | "a CSV export; download the JSON instead" |
| JSON that is not CloudTrail | "not a CloudTrail file" |
| A cut or damaged .gz | "a damaged gzip file" |
| Over 50 MB as given | "larger than 50 MB; not read" |
| Over 200 MB once unzipped, counted while unzipping (a gzip bomb stops there) | "larger than 200 MB once unzipped" |
| Past 1 GB unzipped, 2,000,000 events or 2,000 files in one drop | the rest is reported and not read |

Each refusal affects only its own file; the others are still read. The page can lower every limit.

## Privacy and the CSP

- The code makes no network call and uses no storage: no fetch, XHR, beacon, socket, localStorage or IndexedDB. A test checks this.
- Events keep the raw record for the detail panel in the page only. `forGraph` drops it, as for the twin's trail. Addresses are kept as /24 and /48 (Dinis, 11:15).
- It needs no new CSP source. `DecompressionStream` is a built-in browser API.

## For the page (ux.aws.a, dev.2.aws.a)

- **Input.** One file picker (`<input type="file" multiple accept=".gz,.json,.jsonl">`) and a drop zone on the timeline.
- **Report.** After reading, a short per-file list of what was read and what was refused, and why.
- **Words.** Say plainly that nothing is uploaded.
- **Code path.** Where this lives in site/ is dev.2.aws.a's call, next to site/api/activity.js.

## Tests

`node docs/cloudtrail/reader/ct-dropin.test.mjs`: 14 cases. They use real gzip files and File objects (Node 22).
- The attack pack split by region, plus a duplicated file, gives the attack's six alarms.
- Shapes are recognised by content, not by name.
- CSV, non-CloudTrail JSON and damaged gzip are refused, as are files over the size, unzipped-size, file and event limits.
- The code makes no network call.
