# CloudTrail: the one event shape every view reads

Written by cloudtrail.aws.a@SovereignWebsite.dinis, 23 Nov 2026, 04:31 UTC wake. Step 2 of the first note: the reader turns any CloudTrail input into one list of events in this shape, and the timeline, per-asset activity and alarms read only that list. Read against site/twin.js at dev 1be7f7f with the live-trail patch (docs/cloudtrail/patches/2026-11-23__01-live-trail.patch). No live AWS. *To check* marks go to boto3.aws.c.

## Why one shape

A first-time user drops in a file, or opens the twin, and sees the same three views either way. If each view read raw records, each would repeat the same guesses (who is this, what did they touch, did it fail) and get them differently. One reader, one shape, one place to test.

## The shape

```
{
  id:        "00000000-0000-4000-8000-000000000101",  // eventID; duplicates dropped on it
  time:      1795341842000,                          // eventTime as ms since 1970 (UTC), for sorting and the brush
  iso:       "2026-11-22T10:04:02Z",                  // eventTime as written, for display
  service:   "iam",                                  // eventSource less ".amazonaws.com"
  action:    "UpdateAssumeRolePolicy",               // eventName
  region:    "us-east-1",                            // awsRegion
  account:   "111122223333",                         // recipientAccountId
  who: {
    kind:    "role" | "user" | "root" | "web" | "service" | "unknown",
    name:    "sws-aws-platform-change",              // short, for the line
    arn:     "arn:aws:iam::111122223333:role/sws-aws-platform-change",  // the role or user, not the session
    via:     "accounts.google.com"                   // web identity provider, or invokedBy service, if any
  },
  from:      { net: "203.0.113.0/24", service: null, city: null, country: null, agent: "Mozilla/5.0" },  // network only (privacy, below)
  change:    true,                                   // !readOnly; missing readOnly counts as a change (safer)
  category:  "Management" | "Data" | "Insight" | "NetworkActivity",
  failed:    null | { code: "AccessDenied", message: "..." },
  targets:   [ { type: "iam:role", id: "sovereignwebsite-factory-dns",
                 arn: "arn:aws:iam::111122223333:role/sovereignwebsite-factory-dns" } ],
  words:     "the change role rewrote who may assume the role sovereignwebsite-factory-dns",
  raw:       { ... }                                 // the record as read, untouched, for the detail panel
}
```

Rules:

- **Nothing is invented.** A field the record lacks stays null; the line says "unknown" rather than guess.
- **`raw` is kept as data, never as HTML.** Every view writes it through textContent (as site/s3.js does).
- **`targets` uses the same ids as ontology.aws.a's graph** (ARNs where AWS has them), so a click on a target opens that asset in the graph and its per-asset activity. Type names to agree with ontology.

## Who

From `userIdentity`:

| `userIdentity.type` | `who.kind` | `who.name` | `who.arn` |
|---|---|---|---|
| AssumedRole | role | `sessionContext.sessionIssuer.userName` | `sessionContext.sessionIssuer.arn` |
| IAMUser | user | `userName` | `arn` |
| Root | root | "the account root" | `arn` |
| WebIdentityUser | web | `userName` | null; `via` = `identityProvider` |
| AWSService | service | `invokedBy` | null |
| anything else | unknown | `type` | `arn` if present |

`via` also takes `userIdentity.invokedBy` (a service acting for someone) and `sessionContext.webIdFederationData.federatedProvider` (this hub signs in with Google). The role, not the session, is the "who": sessions change every hour, the role is what a user recognises.

## Targets, per action (first set)

What each call touched, from `requestParameters` (and `responseElements` where the request does not name it). This list covers every call the twin makes today; others fall back to "any parameter named `bucketName`, `roleName`, `stackName`, `functionName`, `policyArn`" and else no target.

| Service | Action | Target |
|---|---|---|
| s3 | any, with `bucketName` | `s3:bucket` bucketName (and `s3:object` bucketName/key if `key`) |
| iam | UpdateAssumeRolePolicy, PutRolePolicy, AttachRolePolicy, DetachRolePolicy, DeleteRolePolicy, GetRole | `iam:role` roleName |
| iam | CreatePolicyVersion | `iam:policy` policyArn |
| sts | AssumeRoleWithWebIdentity, AssumeRole | `iam:role` from `roleArn` |
| cloudformation | CreateChangeSet, ExecuteChangeSet, UpdateStack, DescribeStacks | `cloudformation:stack` stackName |
| cloudcontrolapi | UpdateResource, GetResource | from `typeName` and `identifier` (AWS::S3::Bucket gives `s3:bucket`) |
| cloudtrail | StopLogging, DeleteTrail, PutEventSelectors | `cloudtrail:trail` name |

## Words

A sentence per known action, built from the shape, not from raw text: "**who** *verb* **target**", plus "(refused: AccessDenied)" when `failed`. First verbs:

| Action | Words |
|---|---|
| AssumeRoleWithWebIdentity | signed in to *role* with Google |
| UpdateAssumeRolePolicy | rewrote who may assume *role* |
| PutRolePolicy / AttachRolePolicy | gave *role* new permissions |
| CreateChangeSet | prepared a change to stack *stack* |
| ExecuteChangeSet | applied a change to stack *stack* |
| UpdateResource (S3 bucket) | changed the settings of bucket *bucket* |
| GetObject | read *key* in *bucket* |
| ListObjectsV2 / ListBucket | listed *bucket* |
| StopLogging | stopped the trail *trail* |
| anything else | called *Action* on *service* |

The role names get a plain label where the hub knows them: `sws-aws-platform-read` is "the read role", `sws-aws-platform-change` "the change role".

## Inputs the reader accepts

In order of work:

1. **CloudTrail log files** as delivered to S3: `{"Records": [...]}`, as `.json` or `.json.gz`, one or many, or a zip of a downloaded `AWSLogs/` folder (read by byte ranges with zip.js). This is what the twin writes. Confirmed by the twin's own files and the documented file layout.
2. **LookupEvents output**: `{"Events": [{ "CloudTrailEvent": "<the record as a JSON string>", ... }]}`; the reader parses each `CloudTrailEvent`. *To check* the exact wrapper, and whether the console's event history download is this shape or another.
3. **CloudWatch Logs export** of a trail sent to CloudWatch Logs: one record per line. *To check.*

Anything else: the page says plainly which shapes it reads, shows the first lines of the file as text, and stops. No guessing.

## Privacy

Dinis Cruz, 23 Nov 2026 ~11:15 UTC (docs/data design 01): anything kept or written out holds only the network, /24 for IPv4 and /48 for IPv6, plus city and country when an enricher gives them; never the raw address. So `from.net` replaces the address; `from.service` holds an AWS service name when CloudTrail puts one in `sourceIPAddress`; `raw` (which still has the address) stays in the page for the detail panel and is never handed on (`forGraph` drops it). The "new address" alarm is a "new network" alarm.

## Limits (for security.aws.c)

- Cap: unzip up to a set size per file and in total (proposal: 200 MB unzipped, then stop with a count of what was read); records past the cap are counted, not read.
- Never fetch a URL, ARN or host found in a record. No new network calls, no CSP change.
- Strings from records are shown with textContent only; nothing from a record becomes an attribute name, a URL or HTML.

## Tests (when a code path is agreed)

Each asserts the shape above, field by field, and the words.
