AWS Platform Sovereign Website

Run your AWS accounts from your own browser. Sign in with Google; AWS gives this page credentials for one hour, for roles you wrote as code. Read-only unless you approve a plan. No AWS key is ever made.

The owner has not set this site's Google client ID yet (config.js).

Your AWS accounts

Kept in this browser only, sealed with its key; never on the page or in any repository.

Start here: connect your first AWS account

  1. Add it below: a name for you, and its 12-digit account ID (top right of the AWS console).
  2. Set it up once: download its template and create one CloudFormation stack in that account. It makes two roles that trust only your Google account through this site; no AWS key is made.
  3. Read it: press the account's Read button. From then on S3, Costs, Stacks, IAM and the other tabs work on it.

          Costs

          This month so far, by service and by region, the last 30 days, the forecast to the month end and your budgets. Read with the read role (Cost Explorer and Budgets). Reads only.

          Stacks and DNS

          Activity

          What was done in the account, from CloudTrail's event history (the last 90 days, one region at a time): what this site's browser sessions did, changes only, or everything. Reads only.

          Feedback

          Tell the agents what to fix or build next, and share parts of your account so they know what is there. Nothing is sent until you press Send.

          How it works

          • Google gives this page an ID token for you. AWS STS (AssumeRoleWithWebIdentity) swaps it for credentials that end within the hour.
          • So a refresh does not sign you out, the page seals both with this browser's own key: a key pair made for this site whose private half cannot be read by anyone, this page included. Sealed records end when the credentials do. Sign out deletes them; Forget this device also deletes the key.
          • Once you have signed in here by hand, Google signs you in again without a click when this browser knows you. Sign out turns that off until you next sign in by hand.
          • Your roles are the mandate: written as infrastructure as code, a role can do only what its template lists.
          • Calls go from your browser straight to AWS (STS, IAM, Cost Explorer, CloudFormation, Cloud Control, S3), signed in the page. No server of ours sits in between, and there is no tracking.
